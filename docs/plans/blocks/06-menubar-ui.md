# Block 06 — Menubar UI + live indicator

Зависимости: 04, 05.

## Задача

Показать, что приложение живо и что оно сейчас видит. У продукта без окна иконка в меню-баре — единственный канал обратной связи.

## Объём

- `Ajar/UI/MenuBarIconView.swift` — иконка состояния: обычная в `normal`, с отметкой активной зоны в `low`/`stop`, приглушённая при подавлении или паузе, с предупреждением при `currentAngle == nil` (датчик пропал). SF Symbols, шаблонное изображение — само подстраивается под тему.
- `Ajar/UI/MenuBarPopoverView.swift`:
  - Текущий угол крупно и текущая зона словом.
  - Что произойдёт в каждой зоне — одна строка на зону, читается как объяснение, а не как настройка.
  - Тумблер паузы (Block 05).
  - Строка состояния подавления, когда оно активно: «Paused — external display connected», а не молчание.
  - Кнопки Settings (заглушка до Block 07) и Quit.
- `Ajar/UI/MenuBarViewModel.swift` — чистая структура: `(angle, zone, suppression, tier) → строки для попапа`. Тестируется без SwiftUI.
- Если датчик не найден — попап показывает честное «This Mac has no lid angle sensor» и ссылку на страницу совместимости, а не пустоту.

## Ручной чек-лист

1. Иконка меняется при движении крышки, отставание от реального положения не заметно глазом.
2. Попап открывается кликом, угол в нём обновляется живьём.
3. Подключение внешнего монитора при закрытой крышке отражается строкой подавления.

## Acceptance

- Unit-тесты `MenuBarViewModel`: строки для каждой зоны, состояние подавления, `angle == nil`, Free против Pro.
- Чек-лист пройден, результаты в STATUS.md.
- Известное ограничение автоматизации: синтетический клик по `NSStatusItem` попап открывает нестабильно. Визуальную проверку попапа записывать как задачу владельцу, а не имитировать.
