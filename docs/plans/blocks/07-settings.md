# Block 07 — Settings + calibration UI

Зависимости: 06.

## Задача

Окно настроек, в котором главный элемент — живой индикатор угла. Пользователь двигает крышку и видит, как ползёт стрелка и подсвечивается зона. Это одновременно настройка, демонстрация продукта и инструмент отладки для нас.

## Объём

- `Ajar/UI/SettingsView.swift` — сцена `Settings`, три вкладки:
  - **General:** launch at login (`SMAppService.mainApp` через тонкую обёртку `Ajar/App/LaunchAtLogin.swift`), глобальная пауза, выбор действия для зоны `low` (в Free — только встроенный мьют).
  - **Zones:** живой индикатор угла (горизонтальная шкала 0…`maxAngle` с закрашенными зонами и бегунком текущего угла), слайдеры `lowThreshold`, `hysteresis`, `dwell`, кнопка «Calibrate maximum» → трёхсекундный замер с инструкцией «push the lid until it stops».
  - **About:** версия, ссылка на сайт, поле ввода лицензионного ключа (заглушка до Block 09), «Check for updates» (заглушка до Block 11).
- Изменение любого порога применяется немедленно, без перезапуска, и сразу видно на индикаторе.
- Некорректные комбинации (порог выше максимума и т.п.) не сохраняются: поле подсвечивается, значение откатывается. Валидация — на уровне `Calibration`, не в вью.

## Ручной чек-лист

1. Индикатор угла двигается синхронно с крышкой, подсветка зоны совпадает с реальным поведением.
2. Калибровка максимума: толчок до упора записывает 131° (на тестовой машине), отказ при попытке калибровать из рабочего положения.
3. Launch at login: тумблер включён → `sfltool dumpbtm` подтверждает регистрацию login item; выключен → снят.
4. Пороги переживают перезапуск приложения.

## Acceptance

- Unit-тесты валидации `Calibration` (границы, взаимный порядок порогов, откат некорректного значения).
- Чек-лист пройден, результаты в STATUS.md. Регистрацию login item проверять фактом (`sfltool dumpbtm`), а не тем, что тумблер визуально включился.
