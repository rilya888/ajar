# Block 02 — LidAngleReader

Зависимости: 01.

## Задача

Единственный слой, который трогает IOKit. Даёт остальному приложению один наблюдаемый `Int?` и больше ничего.

## Объём

- `Ajar/Sensor/LidAngleReader.swift`:
  - `IOHIDManagerCreate` + matching строго по `kIOHIDDeviceUsagePageKey = 0x20`, `kIOHIDDeviceUsageKey = 0x8A`. По VendorID/ProductID не матчить.
  - Чтение `IOHIDDeviceGetReport(.feature, reportID: 1)`, буфер 8 байт, угол = `Int(buf[1]) | Int(buf[2]) << 8`.
  - Опрос 20 Гц на фоновой очереди (`DispatchSourceTimer`), публикация в главную очередь **только при изменении** значения.
  - `@Observable private(set) var currentAngle: Int?` — `nil` означает «датчика нет или он пропал».
  - `IOHIDManagerRegisterDeviceMatchingCallback` / `...RemovalCallback`: устройство пропало → `currentAngle = nil`, появилось → возобновить опрос. Ошибка одного чтения не роняет таймер и не сбрасывает значение в `nil` (сбрасывает только removal или N подряд неудачных чтений).
  - `start()` / `stop()`, безопасный повторный вызов.
- Константа частоты опроса — в одном месте, рядом с остальными настройками.
- `AppState` создаёт reader и стартует его.

## Ручной чек-лист (на реальном железе, результат в STATUS.md)

1. Приложение запущено, угол в логе меняется при движении крышки, совпадает с `Tools/lidangle.swift` в пределах градуса.
2. Задержка от движения до нового значения < 100 мс.
3. Сон/пробуждение по сценарию Block 01: reader восстанавливается сам, без перезапуска приложения.
4. Приложение живёт час без роста памяти и без спама в логе.

## Acceptance

- Unit-тесты на разбор отчёта (чистая функция «байты → угол», включая мусорный/короткий ответ) и на политику `nil` (N неудачных чтений).
- Чек-лист пройден, результаты в STATUS.md.
- На машине без датчика (если доступна) `currentAngle` остаётся `nil`, приложение не падает.

## Коммит

`feat(sensor): read lid angle via public iohidmanager`
