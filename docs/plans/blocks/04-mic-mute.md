# Block 04 — Mic mute action

Зависимости: 03.

## Задача

Единственное встроенное действие: прикрыл крышку — микрофон замолчал, открыл — вернулся ровно в то состояние, в котором был. После этого блока продукт существует.

## Объём

- `Ajar/Actions/MicMuter.swift`:
  - Устройство — `kAudioHardwarePropertyDefaultInputDevice`.
  - Основной путь: `kAudioDevicePropertyMute`, scope `kAudioObjectPropertyScopeInput`.
  - Fallback: если `AudioObjectHasProperty` для `Mute` возвращает false — `kAudioDevicePropertyVolumeScalar = 0`. Применённый способ и прежнее значение громкости запоминаются, восстановление идёт тем же способом.
  - Запоминается `AudioObjectID` устройства, которое мьютили: если во время зоны пользователь переключил вход (подключил наушники), размьючиваем то, что мьютили, а не текущее по умолчанию.
- `Ajar/Actions/MuteRestoreState.swift` — **чистая** логика восстановления, отдельно от CoreAudio:
  - При входе в зону запоминаем состояние до вмешательства.
  - Если микрофон уже был выключен пользователем — не трогаем ничего ни на входе, ни на выходе.
  - Если пользователь сам включил микрофон, пока крышка была прикрыта, — на выходе не трогаем.
  - Восстанавливаем только то, что изменили сами.
- `AppState` связывает `ZoneTracker` с `MicMuter`: вход в `low` → mute, выход из `low` → restore.

## Ручной чек-лист (на реальном железе, результат в STATUS.md)

1. Встроенный микрофон: прикрыл → в System Settings ▸ Sound ▸ Input вход замьючен; открыл → вернулось. Оранжевый индикатор macOS погас, пока шла запись.
2. Проверить, поддерживает ли встроенный вход `kAudioDevicePropertyMute`, или сработал fallback. Записать в STATUS.md — от этого зависит текст в онбординге.
3. Bluetooth-гарнитура и/или USB-микрофон, если есть: тот же сценарий.
4. Микрофон был выключен пользователем ДО жеста → после цикла остался выключенным.
5. Пользователь включил микрофон, пока крышка прикрыта → после открытия остался включённым.
6. Смена устройства входа во время прикрытой крышки → размьютилось то устройство, которое мьютили.
7. Задержка от достижения зоны (плюс `dwell`) до фактического мьюта < 200 мс.

## Acceptance

- Unit-тесты `MuteRestoreState` на все четыре комбинации «было выключено / было включено» × «пользователь вмешался / не вмешался».
- Чек-лист пройден, результаты в STATUS.md.
- Явно записать в STATUS.md, что Zoom/Meet после системного мьюта показывают микрофон включённым — это входит в текст онбординга (Block 10).
