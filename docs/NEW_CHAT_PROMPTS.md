# Промты для новых чатов

Запускайте блоки строго по порядку зависимостей (см. `STATUS.md`). Один чат — один блок. Скопируйте универсальный промт, подставив номер блока и имя файла; после финального ответа закройте чат.

## Универсальный промт

```text
Выполни только Block NN проекта Ajar.

Прочитай по порядку:
1) CLAUDE.md;
2) docs/PRODUCT.md;
3) нужные твоему блоку разделы docs/ARCHITECTURE.md;
4) docs/plans/blocks/NN-<имя>.md;
5) docs/STATUS.md, включая раздел «Замеры на железе».

Проверь, что зависимости блока complete, и посмотри git log. Реализуй блок в границах его файла: чистую логику — с unit-тестами, железные проверки — по ручному чек-листу блока. Выполни acceptance criteria, обнови свою строку и «Последний результат» в docs/STATUS.md, сделай указанный в блоке коммит.

Не выполняй другие блоки, не рефакторь соседние модули, не делай push, не добавляй зависимости и не создавай подагентов без моего разрешения.

Если блок требует физического движения крышки — дай мне точную инструкцию («откройте до упора, подержите 3 секунды») и дождись, не выдумывай данные.

Пиши в caveman-стиле: без вступлений, пересказов документации и планов на будущее, минимум текста между действиями. В конце дай только: результат, проверки, hash коммита, ограничения, следующий разрешённый блок.
```

## Какая модель на какой блок

Критерий — не «сложность», а **цена ошибки и то, поймает ли её тест**. Там, где баг тихий (лицензия, восстановление микрофона) или трудно диагностируемый (указатели IOKit, нотаризация), берём Opus. Там, где спека полная и промах ловится компилятором или юнит-тестом, хватает Sonnet.

| Блок | Модель | Почему |
|---|---|---|
| 00 Project foundation | Sonnet | Механика. Единственное скользкое место — руками собранный `pbxproj`; если два раза подряд не собирается, перезапустить блок на Opus, а не доламывать |
| 01 Sensor spike | Sonnet | Осталась только clamshell-проверка и решение «нужен ли код вообще» — решение уже подготовлено замерами |
| 02 LidAngleReader | **Opus** | C-API IOKit из Swift: указатели, колбэки, буферы, потоки. Ошибка здесь выглядит как «датчик глючит», а не как краш |
| 03 Zone engine | Sonnet | Самый подробно описанный блок проекта, чистые функции, всё ловится тестами. Трудное думание уже сделано |
| 04 Mic mute | **Opus** | CoreAudio капризен, а логика честного восстановления состояния — тихая: сломается так, что заметит только пользователь, у которого микрофон не вернулся |
| 05 Suppression | Sonnet | Нотификации плюс чистые флаги. Судейское решение по clamshell расписано в блоке |
| 06 Menubar UI | Sonnet | SwiftUI, видно глазами |
| 07 Settings | Sonnet | SwiftUI плюс валидация, всё проверяемо |
| 08 Shortcuts runner | Sonnet | Умеренно. Если упрётся в решение о задержке — это остановка и вопрос владельцу, а не задача для модели помощнее |
| 09 Licensing | **Opus** | Деньги и криптоподпись. Проверка лицензии, ошибочная в тихую сторону, обнаруживается через месяц по возвратам |
| 10 Onboarding | Sonnet | Экраны и флаги |
| 11 Release | **Opus** | Подпись, нотаризация, Sparkle. Точные заклинания с невнятными сообщениями об ошибках — худшее место для угадывания |

Haiku блоки не ведёт: любой из них заканчивается записью в STATUS.md, а это суждение о том, что было измерено. Но для разбора логов замеров, обновления таблицы совместимости и правки appcast он подходит.

Правило переключения: если блок на Sonnet дважды подряд споткнулся об одну и ту же ошибку — не третья попытка, а перезапуск блока на Opus с чистого контекста.

## Параллельность

Можно вести параллельно (независимые ветки зависимостей): 04 ∥ 05, 08 ∥ 09 ∥ 10. Если работаете в одном чате подряд — всё равно по одному блоку за чат, это защита от расползания контекста.

## Особенность этого проекта

Половина проверок требует руки на крышке. Агент не может ни подвигать её, ни подсмотреть результат — только попросить и разобрать лог. Поэтому в каждом железном блоке инструкция владельцу формулируется до начала прогона, одним сообщением, с точными фазами и длительностями: «откройте до упора, подержите 3 секунды, затем прикройте ниже 30°, подержите 3 секунды». Разбор — по run-length-свёртке лога, как в разведке 2026-08-11.
