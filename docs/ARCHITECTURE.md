# Ajar — архитектура

Один процесс, менюбар-приложение SwiftUI (`MenuBarExtra`). Без песочницы, без демонов, без XPC, без базы данных. Приложение должно быть запущено, чтобы реагировать на крышку (автозапуск через `SMAppService`).

## Слои и поток данных

```
IOHIDManager  (HID-устройство "las", usage page 0x20 / usage 0x8A)
      │  feature report ID 1, опрос 20 Гц
      ▼
LidAngleReader ──► currentAngle: Int?   (@Observable, nil = датчик недоступен)
      │
      ▼
ZoneEngine  (чистая функция: угол + Calibration + предыдущая зона → Zone)
      │  гистерезис 2°, удержание 1 с
      ▼
ZoneTransition (.entered(zone) / .exited(zone))
      │
      ├──────────────► Suppressor  ── подавлено? ──► ничего не происходит
      │                (сон, clamshell, внешний монитор, стартовая пауза)
      ▼
ActionRouter
      ├──► MicMuter        (CoreAudio, Free)
      └──► ShortcutRunner  (Shortcuts, Pro)
      │
      ▼
UI (MenuBarExtra, Settings с живым индикатором, Onboarding, Paywall)
```

Единственное состояние на диске — `UserDefaults`. Никакой персистентности событий: приложение не ведёт историю.

## Sensor: LidAngleReader

```swift
final class LidAngleReader {          // Sensor/
    @Observable private(set) var currentAngle: Int?   // nil = устройства нет
    func start()                       // matching + таймер опроса
    func stop()
}
```

- Matching: `kIOHIDDeviceUsagePageKey = 0x20`, `kIOHIDDeviceUsageKey = 0x8A`. Только эти два ключа — по VendorID не матчим, чтобы не отвалиться на будущих ревизиях.
- Чтение: `IOHIDDeviceGetReport(device, kIOHIDReportTypeFeature, 1, &buf, &len)`, буфер 8 байт. Ответ — `01 <lo> <hi>`, угол = `Int(buf[1]) | Int(buf[2]) << 8`.
- Опрос 20 Гц на фоновой очереди; публикация в главную очередь только при изменении значения.
- **Сон переживается без вмешательства:** замер показал, что `IOHIDDevice` остаётся валидным через 142-секундный сон, removal-колбэка не приходит, первое же чтение после пробуждения корректно. Переоткрывать устройство не нужно. Обработка removal остаётся только на случай реального отключения: `IOHIDManagerRegisterDeviceRemovalCallback` → `currentAngle = nil`, повторный матчинг. Ошибка чтения не должна ронять цикл опроса.
- `currentAngle == nil` — единственный источник правды для «датчик не поддерживается»; на нём стоит гейт совместимости в онбординге.

Проверено на железе (см. STATUS.md): формат отчёта, публичность API, отсутствие TCC-промптов, нулевой шум в покое.

## Zones: ZoneEngine и Calibration

```swift
enum Zone { case closed, low, normal, stop }

struct Calibration: Codable {         // UserDefaults
    var maxAngle: Int                 // замер при первом запуске, 131 на MacBookPro18,3
    var closedBelow: Int = 3          // закрыто = 0°, последнее ненулевое при закрывании = 4°
    var lowThreshold: Int = 45        // граница зоны «прикрыл»
    var hysteresis: Int = 2
    var dwell: TimeInterval = 1.0
    var stopMargin: Int = 2           // stop = angle >= maxAngle - stopMargin
}

enum ZoneEngine {
    static func zone(angle: Int, previous: Zone, calibration: Calibration) -> Zone
}
```

- **Сглаживания нет.** Шум не превышает ±1°: датчик квантует до целых градусов, и на большинстве положений значение стоит намертво (замеры: 197, 193 и 102 идентичных отсчёта подряд), но если крышка встала ровно на границу кванта — дребезжит постоянно (замер: 39 смен 119↔120 за 19 с). Гистерезис 2° это перекрывает полностью, скользящее среднее только добавило бы задержку. **Отдельно: живой индикатор угла в настройках обязан гасить этот дребезг на уровне отображения** (показывать значение, менявшееся дольше ~300 мс), иначе цифра мигает и выглядит как баг.
- **Гистерезис** применяется к границе только в сторону выхода: находясь в `low`, зона держится до `lowThreshold + hysteresis`. Чистая функция от `(angle, previous, calibration)` — тестируется без железа.
- **Удержание (dwell)** живёт слоем выше, в `ZoneTracker`: смена зоны фиксируется, только если новая зона продержалась `dwell` **и** угол за это окно изменился меньше чем на 3°. Второе условие обязательно, и оно вытекает из замера: при полном закрытии крышка проходит зону `low` за 1,28 с, то есть одного лишь `dwell = 1 с` хватило бы, чтобы обычное закрытие ноутбука коротко мьютило микрофон. Осознанный жест «прикрыл» всегда заканчивается неподвижной крышкой, полное закрытие — никогда. Стабильность угла отличает их надёжнее любого порога по времени.
- **Граница `closed` точная, без гистерезиса.** Замер: полностью закрытая крышка даёт ровно 0°, последнее ненулевое значение при закрывании — 4°, промежуточных 1–3° не существует. Разрыв в 4° разделяет состояния сам.
- **Калибровка максимума** — не «настройка со значением по умолчанию», а обязательный замер: пользователь толкает крышку до упора, приложение берёт максимум за 3 с. Без этого зона `stop` не существует.

## Actions

Роутер получает `ZoneTransition` и вызывает то, что настроено на этот переход. Никакого протокола `Action` с одной реализацией: два конкретных исполнителя, вызываются напрямую.

**MicMuter (Free, Actions/):**
- `kAudioDevicePropertyMute`, scope `kAudioObjectPropertyScopeInput`, на устройстве по умолчанию (`kAudioHardwarePropertyDefaultInputDevice`).
- Не все устройства входа поддерживают `Mute` — если `AudioObjectHasProperty` возвращает false, fallback на `kAudioDevicePropertyVolumeScalar = 0`. Какой путь применён, запоминается, чтобы восстановить тем же способом. Проверить оба на реальном железе — Block 04.
- **Восстановление честное:** при входе в зону запоминается состояние ДО нашего вмешательства. Если пользователь уже держал микрофон выключенным, при выходе из зоны он остаётся выключенным. Если пользователь сам включил микрофон, пока крышка была прикрыта, при выходе мы не трогаем ничего.
- Смена устройства входа во время активной зоны (наушники подключили) — размьючиваем то устройство, которое мьютили, по его AudioObjectID.

**ShortcutRunner (Actions/):** только зона `stop` когда-либо запускает Shortcut — `low` всегда идёт через `MicMuter`, ни в одном тарифе замены нет.
- `NSUserAppleScriptTask` либо `/usr/bin/shortcuts run <name>` через `Process`. Выбор — за Block 08 по факту замера задержки; ожидаемая цена запуска — сотни миллисекунд, для жеста приемлемо.
- Список доступных шорткатов — `shortcuts list`, кэшируется на время работы окна настроек.
- Запуск асинхронный, результат игнорируется, ошибка пишется в лог и показывается в попапе одной строкой. Шорткат, который висит, не должен блокировать реакцию на следующее движение крышки.
- **`DefaultShortcuts` (Actions/ShortcutBindings.swift):** зона `stop` никогда не бывает пустой. Free и триал без выбора пользователя гоняют пару `"Ajar Do Not Disturb"` / `"Ajar Resume Focus"` — включает/выключает DND на входе/выходе из зоны. Эти два подписанных (`shortcuts sign -m anyone`) `.shortcut`-файла лежат на `quietunit.com/ajar/shortcuts/` и ставятся из онбординга одним тапом: `DefaultShortcuts.download(_:)` качает файл **мимо кэша** (`.reloadIgnoringLocalAndRemoteCacheData` — nginx не шлёт `Cache-Control`, и URLSession иначе переставляет протухшую копию по эвристике от `Last-Modified`) во временную папку **под именем самого шортката** и отдаёт его `NSWorkspace.open` — обычный путь двойного клика, Shortcuts проверяет подпись и показывает своё окно «Add Shortcut» (не Accessibility). Схема `shortcuts://import-shortcut?url=...` не годится: на macOS 26 Shortcuts отвергает её через 7 мс после получения URL, не скачивая файл («The shortcut URL provided was invalid»). Имя импортированного шортката берётся из имени файла — поэтому в именах нет двоеточия и поэтому качаем не под серверным именем. Pro/триал может заменить любую из двух на что угодно из `shortcuts list`, отдельно на вход и на выход, в Settings ▸ Zones.
- **Откат при потере Pro:** `ShortcutAction.decide` берёт кастомную привязку из `ShortcutBindings` только когда `tier.unlocksPro`; иначе — всегда дефолт. Привязка при этом не удаляется, только перестаёт читаться — купил лицензию снова, свой Shortcut вернулся сам.

## Lifecycle: Suppressor

Единственное место, где живут все причины «сейчас ничего не делать». Возвращает `isSuppressed(now:) -> Bool`, чистая логика поверх собранных флагов.

| Причина | Как определяем | Почему |
|---|---|---|
| Clamshell с внешним монитором | Крышка закрыта (0°) И среди активных дисплеев есть не-встроенный (`CGDisplayIsBuiltin` по `NSScreenNumber`) | **Вероятно избыточно, см. ниже.** Признак «не спит» для этого не годится: замер показал, что машина держится бодрой с закрытой крышкой и без всякого монитора |
| Сон и пробуждение | `NSWorkspace.willSleepNotification` / `didWakeNotification`, пауза 3 с после пробуждения | Не из-за датчика: замер показал, что первое чтение после сна уже корректно. Пауза нужна потому, что на пробуждении крышка по определению проходит зону `low` |
| Первые 3 с после запуска | Таймер от старта | Иначе автозапуск при логине с прикрытой крышкой сразу что-нибудь сделает |
| Пользователь выключил Ajar | Тумблер в попапе | Явная пауза без выхода из приложения |

Подавление гасит именно действия, а не чтение датчика: живой угол в UI продолжает обновляться, иначе пользователь решит, что приложение зависло. Выход из подавления не запускает отложенные действия — состояние зоны пересчитывается заново.

**Про clamshell отдельно.** Замеры делают его обработку, скорее всего, ненужной: закрытая крышка — это зона `closed`, в которой действий нет по определению, а путь к ней через `low` отсекается требованием стабильности угла. Сценарий «закрыл ноутбук с внешним монитором» безопасен без единой строки clamshell-кода. Поэтому в Block 05 это пункт проверки, а не обязательная функция: код добавляется, только если проверка на реальном мониторе покажет проблему.

## Licensing

```swift
enum Tier { case trial(daysLeft: Int), free, pro }
```

- `TrialManager`: дата первого запуска пишется в файл в Application Support **и** в `UserDefaults`, при вычислении берётся более ранняя. Триал 14 дней. // ponytail: перевод часов назад обманет триал — принимаем, цена вопроса разовая лицензия $9
- `LicenseManager`: ключ вводится пользователем и проверяется **локально** — `base64(payload).base64(signature)`, payload `email|order-id`, подпись Ed25519 (`CryptoKit`), встроенный публичный ключ. Сырой ключ лежит в Keychain и перепроверяется при каждом запуске. Сетевого кода в лицензировании нет вообще, поэтому «оффлайн-запуск» не отдельная функция, а единственный режим.
- Привязки к железу нет и лимита активаций нет: ключ на email работает на всех машинах покупателя. Цена решения — отозвать ключ при возврате нельзя.
- `Tier` — единственный источник правды для гейтов UI. Никаких дублирующих проверок «а купил ли он» в исполнителях действий.

Провайдер — **Paddle Billing**, схема офлайн (вебхук → Worker подписывает ключ приватным ключом владельца). Обоснование и контракт: `docs/release/licensing.md`.

**Этап 1 (free-first, Block 12).** `AppState.tier` прибит к `.pro` флагом `AppState.proUnlockedForFreeStage` — всё разблокировано. UI оплаты убран: пейволл-сцена `Window` удалена, строки «Unlock Pro…» / «Pro» в Settings и строка апселла в попапе сняты, статус лицензии/триала во вкладке About не показывается. Весь код `Ajar/Licensing/` (`TrialManager`, `LicenseManager`, `LicenseVerifier`, `GestureCounter`, `Tier`) остаётся в дереве и под тестами; `PaywallView.swift` лежит недостижимым. Block 13 возвращает настоящую логику одной строкой (`proUnlockedForFreeStage = false`).

## Разрешения и подпись

- **App Sandbox выключен.** Причина: entitlements песочницы дают IOKit только по конечному списку категорий (`usb`, `bluetooth`, `firewire`, `serial`, `audio-video-bridging`, `camera`, `microphone`, `print`), а датчик крышки сидит на внутренней шине и не попадает ни в одну. Это же закрывает Mac App Store как канал.
- **Hardened Runtime включён** — обязателен для нотаризации.
- **TCC-промптов нет ни одного.** Проверено: неподписанный бинарник читает датчик без запроса разрешений. Мьют микрофона через CoreAudio — управление свойством устройства, не захват, промпта тоже не вызывает. Accessibility не запрашивается принципиально.
- Единственное, что пользователь разрешает руками, — Shortcuts при первом запуске шортката (системное поведение, не наш промпт).
- `LSUIElement` = YES (нет иконки в доке).

## Тестовая стратегия

- Unit (XCTest): `ZoneEngine` (все переходы, гистерезис в обе стороны, границы зон, вырожденная калибровка), `ZoneTracker` (удержание), восстановление состояния микрофона (чистая логика «что было до нас»), `Suppressor` (комбинации флагов), `TrialManager` (граница 14 дней, приоритет лицензии, две метки даты), `LicenseVerifier` (разбор ключа и проверка подписи на зафиксированных фикстурах). Keychain — системный слой, проверяется руками.
- Ручные чек-листы на железе: чтение датчика, мьют на разных устройствах входа, сон, clamshell, автозапуск. IOKit и CoreAudio не мокаем.
- Разведочный CLI `Tools/lidangle.swift` остаётся в репозитории — им проверяется железо на новых моделях без сборки приложения.
