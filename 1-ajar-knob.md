# 1. Ajar — петля ноутбука как ручка управления

**Платформа:** macOS (MacBook на Apple Silicon)
**Тип:** менюбар-утилита
**Дистрибуция:** прямая продажа вне Mac App Store
**Статус:** датчик проверен на железе, риск №1 снят

> Это исходная концепция, актуализированная после разведки 2026-08-11.
> Источник правды для разработки — `docs/PRODUCT.md` и `docs/ARCHITECTURE.md`.

---

## Идея

В MacBook на Apple Silicon есть отдельный HID-датчик угла раскрытия крышки. Система использует его для мелочей вроде пробуждения. Для пользователя это просто шарнир — единственный аналоговый орган управления в ноутбуке, о котором никто не думает как об органе управления.

Ajar превращает угол крышки в контроллер:

- **прикрыл, но не закрыл** (ниже настраиваемого порога, по умолчанию 45°) → микрофон в мьют, музыка на паузу; открыл обратно → всё вернулось;
- **толкнул крышку до упора** (упёрлась в ограничитель) → произвольный Shortcut: Focus, DND, что угодно;
- рабочее положение → всё как обычно.

Жест физический, не требует ни клавиш, ни курсора, ни взгляда на экран. Вы «прикрываете» ноутбук, когда встаёте из-за стола, и он сам понимает, что вы вышли.

## Почему это необычно

Все программы для macOS соревнуются за клавиатуру, трекпад и меню-бар — за одни и те же три канала ввода. Здесь используется физический сенсор, который есть у миллионов людей и не задействован ни одним приложением. Это не новая функция, это новый **интерфейс** для старых функций.

Второе перевёрнутое допущение: обычно состояние машины меняется командой. Здесь оно меняется позой машины.

## Что измерено на железе

Разведка проведена 2026-08-11 на MacBook Pro 14" (MacBookPro18,3, M1 Pro, macOS 26). Утилита — `Tools/lidangle.swift`, сырой лог — `docs/research/sweep-2026-08-11.log`.

| Факт | Значение | Следствие |
|---|---|---|
| Устройство | HID `las`, usage page `0x20`, usage `0x8A` | Читается **публичным** `IOHIDManager`, приватный `IOHIDEventSystemClient` не нужен |
| Формат | feature report ID 1, 3 байта: `01 <lo> <hi>` | Угол = LE16 из байтов 1–2, целые градусы |
| Разрешения | ни одного промпта, неподписанный бинарник читает | TCC не помеха; стена только в App Sandbox |
| Шум | **не больше ±1°** — на большинстве положений ноль, но на границе кванта дребезжит постоянно | Сглаживание не нужно, гистерезиса 2° хватает; индикатор в UI дребезг гасит |
| Закрытая крышка | ровно **0°**, последнее ненулевое при закрывании — 4° | Разрыв в 4° разделяет «прикрыл» и «закрыл» сам, без эвристик |
| Сон | пережит: 142 с сна, ноль ошибок, первое чтение после пробуждения корректно | Переоткрывать устройство после сна не нужно |
| Максимум | **131°**, дребезг 130↔131 под нажимом | Механический упор; у моделей различается — калибровать |
| Рабочее положение | 115° и 119° | Всего 12° до упора: фиксированный порог «>125°» нерабочий |
| Минимум (проверен) | 15°, стабильно | Порог 45° лежит глубоко внутри рабочего диапазона |
| Скорость движения | 12° между отсчётами на 10 Гц | Опрашивать на 20 Гц |

**Главное следствие.** Верхняя зона из первой редакции («>125°») отделена от обычной рабочей позы шестью градусами — Focus включался бы случайно при каждом поправлении экрана. Заменена на жест **«толкнуть до упора»**: `угол ≥ max − 2°`, где `max` замеряется при первом запуске. Это не диапазон, а физическое действие с тактильным подтверждением — промахнуться невозможно, и оно само калибруется под любую модель.

**Не проверено:** чтение в clamshell с внешним монитором — на машине разработки монитора нет. Это единственный остаток Block 01, и он, возможно, не потребует кода вообще (см. `docs/STATUS.md`).

## Техническая основа

**Чтение.** `IOHIDManager` с matching по `kIOHIDDeviceUsagePageKey = 0x20` / `kIOHIDDeviceUsageKey = 0x8A`, `IOHIDDeviceGetReport(.feature, id: 1)`, опрос 20 Гц. Только публичный API — это то, что переживает обновления macOS.

**Действия — гибридная модель:**

| Действие | Как делать | Почему так |
|---|---|---|
| Мьют микрофона | Встроенно: CoreAudio `kAudioDevicePropertyMute` на устройстве входа, fallback `kAudioDevicePropertyVolumeScalar` = 0 | В Shortcuts нет действия для мьюта микрофона — сделать снаружи нечем |
| Всё остальное (Focus, DND, пауза, яркость, сцены) | Запуск пользовательского Shortcut на переходе зоны | Ноль приватных API, ноль запросов Accessibility, пользователь собирает что хочет |

Отвергнуто сознательно: `CGEventPost` для медиа-клавиш (требует Accessibility и второго системного промпта), `DisplayServices` для яркости (приватный фреймворк). Обе задачи закрываются шорткатами.

**UI:** `MenuBarExtra` (SwiftUI). Окно настроек с живым индикатором угла.

## Зоны

```
closed  ─── прикрыл ──── рабочая зона ──── упор
  │            │              │              │
 0°..X       X..45°        45°..129°       130°..131°
подавлено   действия      ничего        действия (Pro)
```

`X` — порог «закрыто», определяется в Block 01. Гистерезис 2°, задержка удержания 1 с перед срабатыванием (закрытие занимает ~3 с — за это время зона пересекается один раз, а не дребезжит).

## MVP

Одна вещь, работающая безупречно: **прикрыл крышку → микрофон выключился, приоткрыл → вернулся.** Это уже полезно людям на созвонах и объясняется одним предложением.

Честное ограничение, которое надо сказать вслух в онбординге: системный мьют не сообщает Zoom, что вас не слышно. Оранжевый индикатор macOS погаснет, но в интерфейсе звонка вы останетесь «с включённым микрофоном». Кому нужен мьют внутри приложения — тот вешает на зону свой Shortcut.

## Модель монетизации

Freemium, вне App Store. Скачивание бесплатное — иначе человек платит до того, как узнает, что на его машине нет датчика.

- **Free:** живой индикатор, нижняя зона, встроенный мьют микрофона, автозапуск.
- **Pro ($9 разово):** зона упора, произвольные Shortcuts на любой переход зоны.
- **Триал:** 14 дней всего Pro от первого запуска.

Расходы: $99/год Apple Developer (нужен для нотаризации), ~5% комиссии merchant of record. Порог безубыточности — около десятка продаж в год.

## План

Разбит на 12 блоков, по одному на чат. Таблица зависимостей — `docs/plans/ROADMAP.md`, детали — `docs/plans/blocks/`.

Критический путь: Block 01 (закрытая крышка, сон, clamshell) → 02 (чтение) → 03 (зоны) → 04 (мьют). После Block 04 существует работающий MVP; всё остальное — обвязка.

Реалистично: 2–3 недели вечерами.

## Риски

- ~~**Датчик может отсутствовать или не читаться.**~~ Снят: читается публичным API на M1 Pro. Остаётся совместимость: на MacBook Air M1 2020 и 13" Pro 2020 датчика, по имеющимся данным, нет. Митигация — приложение само проверяет наличие при первом запуске и честно говорит «не поддерживается», до всякой оплаты; таблица совместимости на сайте пополняется по мере отчётов.
- **Apple может закрыть доступ.** Публичный `IOHIDManager` — самый долгоживущий из доступных путей, но гарантий нет.
- **Clamshell с внешним монитором:** закрытая крышка не должна ничего выключать. Явное подавление, Block 05.
- **Ложные срабатывания в дороге:** задержка удержания 1 с вместо детекции движения.
- **Имя.** Решено: Ajar. Рабочее «Hinge» отброшено — так называется крупное приложение для знакомств, и органический поиск был бы утоплен. Ajar — обычное слово, поэтому опорой в поиске станут домен и страница совместимости, а не само имя.

## Дистрибуция

Mac App Store невозможен, и причина точнее, чем «плохо живут в песочнице»: App Sandbox допускает доступ к IOKit только по конечному списку entitlements (`usb`, `bluetooth`, `firewire`, `serial`, `audio-video-bridging`, `camera`, `microphone`, `print`). Датчик крышки сидит на внутренней шине и не попадает ни в одну категорию — стена держится даже при полностью публичном пути чтения.

Прямая продажа: Developer ID, нотаризованный DMG, Sparkle для обновлений, merchant of record для платежей и лицензий. Аудитория — люди на созвонах и любители нестандартного железа; такое хорошо расходится на Hacker News и в MacRumors ровно из-за неожиданности.
