# Ajar — правила для ИИ-агентов

Менюбар-утилита для macOS, превращающая угол раскрытия крышки MacBook в орган управления: прикрыл экран — микрофон в мьют, толкнул до упора — сработал пользовательский Shortcut. Дистрибуция прямая (вне Mac App Store). Freemium: 14 дней полного триала → бесплатный базовый режим, Pro за $9 (разовая лицензия).

## Что читать в новом чате

Читайте только этот минимальный набор, строго по порядку:

1. `CLAUDE.md` — этот файл, правила проекта.
2. `docs/PRODUCT.md` — что мы делаем и почему (продукт, Free/Pro, цена).
3. `docs/ARCHITECTURE.md` — только разделы, нужные вашему блоку.
4. Только назначенный файл из `docs/plans/blocks/`.
5. `docs/STATUS.md` — статусы блоков, результат предыдущего и **замеры на железе**.

`1-ajar-knob.md` в корне — концепция для человека, актуализирована, но источником правды не является: при расхождении верны PRODUCT.md и ARCHITECTURE.md.

Приоритет требований: текущий запрос владельца → CLAUDE.md → PRODUCT.md / ARCHITECTURE.md → файл блока. При противоречии остановитесь и спросите владельца.

## Режим одного блока

- Один чат выполняет ровно один блок из `docs/plans/ROADMAP.md`.
- Перед стартом проверьте в `docs/STATUS.md`, что зависимости блока `complete`.
- Не начинайте следующий блок, даже если осталось время.
- Не рефакторьте соседние модули без необходимости для текущего блока.
- В конце обновите свою строку в `docs/STATUS.md` и раздел «Последний результат».
- Один блок = один логичный коммит (или короткая серия, если указана в блоке).

## Правила реализации

- Язык документации: русский. Код, идентификаторы, коммиты, UI-тексты: английский (v1.0 — English only).
- Стек: Swift 5.10+, SwiftUI (`MenuBarExtra`), IOKit HID, CoreAudio, `SMAppService`. Минимум macOS 14.0.
- **App Sandbox выключен.** Это не небрежность, а вынужденное решение: песочница допускает IOKit только по конечному списку entitlements, и датчик крышки в него не входит. Hardened Runtime — включён (обязателен для нотаризации).
- **Только публичные API.** Датчик читается через `IOHIDManager` (usage page `0x20`, usage `0x8A`) — проверено на железе. `IOHIDEventSystemClient`, `DisplayServices` и прочие приватные фреймворки запрещены: их поломка при обновлении macOS убивает продукт, у которого нет канала быстрой доставки фикса.
- **Никаких запросов Accessibility.** Это отдельный системный промпт и отдельная причина не устанавливать приложение. Всё, что требовало бы `CGEventPost`, делается пользовательским Shortcut.
- Настройки живут в `UserDefaults`. Базы данных в проекте нет и не нужно — приложение не хранит историю.
- Сеть используется ровно в двух местах: активация лицензии и проверка обновлений Sparkle. Больше никаких сетевых вызовов, аналитики и телеметрии.
- Единственная разрешённая сторонняя зависимость — **Sparkle**, и только в Block 11. Любая другая — с явного разрешения владельца.
- Чистая логика (зоны, гистерезис, удержание, калибровка, состояние триала и лицензии, восстановление состояния микрофона) покрывается unit-тестами. Слои железа (HID, CoreAudio, сон/clamshell) проверяются вручную по чек-листу из файла блока — это нормально, не имитируйте «тесты» через моки IOKit.
- Датчик — железо: оставляйте калибровочную ручку, а не только меньше кода. Максимальный угол, пороги зон, гистерезис и время удержания обязаны быть настраиваемыми константами в одном месте.
- Не добавляйте абстракции, которые не нужны текущему блоку. Протокол с одной реализацией — не архитектура, а долг.
- Стиль общения — caveman: коротко, без вступлений, пересказов документации и лишних объяснений. Код и результат вместо прозы; отчёт в конце — только факты по шаблону промта.

## Ограничения

- Не делайте `git push`, платные вызовы и подагентов без разрешения владельца.
- Сборку проверяйте через `xcodebuild build` и `xcodebuild test` (схема Ajar).
- Всё, что требует действий владельца (Apple Developer аккаунт, аккаунт merchant of record, домен, иконка, публикация DMG), фиксируется в `docs/TODO.md`, а не решается самостоятельно.
- Замеры на реальной крышке требуют рук владельца. Если блок упирается в физическое движение крышки — сформулируйте точную инструкцию («откройте до упора, подержите 3 с»), а не имитируйте данные.
